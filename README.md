# PPA 肌膚升級之旅 — DOT TO DOT

純 HTML、CSS、JavaScript 的三關 PPA 活動與十六關自由連連看。自由挑戰保留 48 顆通關星星，活動的進度與星級另外保存。沒有框架、套件、建置步驟、外部字型或網路 API；粉紅水母 PNG 隨專案放在 `assets/`，不依賴其他專案或外部圖片服務。

## 如何遊玩

直接用 Chrome、Edge、Firefox 或 Safari 開啟（或雙擊）`index.html`。請保留 `styles.css`、`campaign.css`、`js/` 與 `assets/` 的相對位置。

活動：首頁 → 開始三關挑戰 → 第一關 → 分數／星級與產品介紹 → 第二關 → 介紹 → 第三關 → 介紹 → 同一完成畫面展開活動與商品資訊。每次按下一步才開始下一關，介紹期間不扣時間。首頁另有逐關重玩按鈕與可直接閱讀的商品／活動資訊區。

自由挑戰：首頁下方「進入自由挑戰」→ 原 16 關選單 → 配對消除 → 通關結算。第 1 關預設解鎖，通關後解鎖下一關，已解鎖關卡可重玩；不插入活動產品卡。

遊戲本身不需要 Node.js，也不需要啟動伺服器。

## 活動內容與進度

- 活動直接使用現有第 1、2、3 關的版型、時間、色數與 PPA 數量（1／2／3 對），不裁切全域 16 關資料，也不改平衡或計分。
- 自由挑戰仍用 `dot-to-dot.v1`；活動使用獨立 `ppa-campaign.v1`，包含各關最佳紀錄與待閱讀的通關介紹。活動通關不改自由挑戰解鎖，反之亦然；音效偏好沿用共用設定。
- 在通關介紹重新整理／返回首頁，主按鈕會接回待閱讀的介紹。在遊戲中重新整理則回到首頁，繼續時重玩第一個未完成活動關卡；不保存半局倒數或盤面。完成三關後可以查看完成資訊，也可以逐關重玩。
- 暫停、失焦與切換分頁沿用原本的時間／Combo 凍結；重玩、換模式、離開會取消舊局延遲。故事與完成資訊沒有遊戲倒數。各畫面切換與介紹更新會把焦點移至標題，dialog 可捲動。
- 活動標題、三關主文、水母銜接語、完成摘要、商品價格與官網網址集中在 `js/campaign.js`，供公司後續審核調整。內容按提供草案呈現，沒有自行新增功效、見效時間或數字。
- 商品資訊為 PPA 30 mL／NT$600、100 mL／NT$1,800；贈禮只顯示「活動優惠與贈禮內容即將公布」。沒有假券、領獎資格、發券、個資蒐集或會員功能。
- 官網按鈕使用提供的 `012s.com.tw` 商品網址，另開分頁並帶 `noopener noreferrer`。遊戲內不進行購物，也不傳送玩家成績。
- 逐關介紹與完成頁角色原檔：`C:/Users/User/Desktop/Codex/ppa-ad-campaign/ads/source/mascot/ppa-jellyfish-pink-guide-v1.png`，原樣複製為本專案 `assets/ppa-jellyfish-pink-guide-v1.png`。首頁另使用 `assets/ppa-pink-guide-holding-product-v1.png`，來源是同素材目錄的抱瓶合成主視覺；不覆寫單獨角色原圖。頁面都用相對網址與 contain 完整呈現插畫；首頁已移除重複的像素瓶裝飾小卡。抱瓶圖為生成式商品示意，包裝小字仍待公司最終核對。

## 遊戲規則

- 點選兩顆相同顏色的寶石，以水平／垂直連線連接，最多轉彎兩次，可以繞棋盤外圍。
- 連線不能穿過其他寶石或牆壁；牆壁不能消除。
- 寶石集合共十五種：紅、藍、黃、綠、黑、白、紫、橘、青、玫紅、萊姆、靛、琥珀、孔雀、珊瑚。每種另有專屬像素符號，輔助辨識相近顏色。
- 每關從該關已開放的集合中隨機抽出固定數量的顏色，再隨機配置成對寶石。第 1～8 關使用原本九種集合；第 9～14 關每關加入一種新寶石，第 14 關起可抽選集合完整擴充到十五種。每關格子、空洞與牆壁位置固定。
- 第 9～16 關包含雙島、四個分離牌區、中央長牆、錯位牌區等版型。分區間的空白可以通行，牆壁仍必須繞開；所有版型都檢查了任意最後兩顆的可連線性。
- 剩餘牌面沒有合法配對時，自動洗牌，只交換仍在場上的寶石，不改變空格、牆壁或各色數量。洗牌動畫暫停關卡與連擊計時。
- 相鄰兩次手動成功消除間隔不超過 5 秒即累積連擊，連擊次數無上限。超過 5 秒未成功配對才中斷；不再有每五次連擊自動消除。
- 第 1～3 關分別加入 1／2／3 對 PPA（2／4／6 顆）。總牌數保持 30／44／48 顆，普通寶石分別為 28／40／42 顆，色數保持 7／7／8；第 4～16 關不加入 PPA。所有 PPA 都是同類型，任意兩顆可用合法路徑配對，沒有固定伴侶。PPA 依實品照片繪製為修長白色圓柱按壓瓶：高透明蓋內可見按壓頭，圓弧瓶肩接白色瓶身，白底搭配紫色小標示與簡化水母。必須由玩家用合法路徑手動配對。
- PPA 底座中央暖白、邊緣淡紫灰，配有冰藍與紫色輪廓光。外框光亮與一至五顆角落星點，直接對應「此刻手動配對 PPA 可觸發的上限」，即 `ppaStrength(combo + 1)`，沒有額外能量值。超過五秒中斷連擊時回到一顆星點；瓶身不閃白，只有外框緩慢呼吸。減少動畫偏好會停用呼吸，保留靜態強度提示。
- PPA 手動配對算一次連擊，初版額外消除對數為 `min(5, max(1, comboAtTrigger))`，其中 `comboAtTrigger` 包含這次 PPA 配對。隨機選擇普通同色目標，忽略路徑限制；不足時只消實際可用對數，可能為零。自動消除不選 PPA、不增加或刷新連擊，也不觸發連鎖。
- PPA 連線與逐對消除演出期間鎖定棋盤、凍結倒數及連擊窗口；暫停、說明、離開確認與失焦可中途凍結演出，繼續後接續剩餘步驟。減少動畫偏好會簡化與縮短演出。演出後才統一檢查通關或洗牌，PPA 也必須清空才能通關。
- 倒數結束前清空寶石即通關；倒數歸零即失敗。最後只剩牆壁也算通關。
- 不同關卡各自使用完整限時、從零計分。

### 星級

以通關當下「剩餘毫秒 ÷ 該關總限時」判定：

| 剩餘比例 | 評價 |
| --- | --- |
| > 50% | 三星 |
| 25%～50%，包含端點 | 二星 |
| > 0%、< 25% | 一星 |
| 0% | 失敗 |

時間條僅保留 25% 與 50% 的標準刻線，不顯示百分比與星級小字；上方同步顯示當前可取得的星級。畫面秒數無條件進位顯示，實際星級用精確時間判斷。

### 分數

- 每組基本 100 分。
- 連擊第 n 次的配對得分為 `100 + (n - 1) × 25`，每次遞增 25 分，不設上限。第 6 次為 225 分，第 10 次為 325 分；連擊中斷後回到 100 分。
- PPA 自動消除每對另加 100 分，僅依實際消除對數計分。PPA 手動配對使用一般連擊分數。
- 通關時，每剩餘 1 秒（無條件進位）加 10 分。
- 例：連消五組普通寶石共 750 分；若第五組是 PPA，且額外消除五對普通寶石，合計 1,250 分（不含通關時間獎勵）。
- PPA 強度與自動消除每對 100 分均為可調的初版設定，集中於 `js/levels.js` 的 `PPA` 及 `js/engine.js` 的 `ppaStrength()`。

## 操作與紀錄

- 滑鼠或觸控點選寶石；再次點選已選寶石可取消。
- Tab 移動焦點，方向鍵在棋盤內移動，Enter／空白鍵選取，Esc 暫停／繼續。
- 暫停會凍結倒數與連擊，並隱藏棋盤。切換分頁或視窗失去焦點時也會自動暫停。
- 右上角可切換音效、開啟說明；音效使用瀏覽器 Web Audio 合成。
- 各關獨立保存最佳星數、最高分與最快通關時間，三個最佳值可以來自不同次挑戰。
- 自由模式沿用原有紀錄，不清除、不重置。取消五擊獎勵、前三關加入 PPA，以及連擊窗口放寬至五秒，會影響分數與耗時，舊新紀錄不完全可比。新活動模式獨立保存，沒有版本排行榜。
- 舊版已通關第 8 關的紀錄，更新後自動解鎖第 9 關；已解鎖第 8 關但尚未通關者，仍需先通過第 8 關。原有分數、星級與音效設定會保留。
- 紀錄使用此瀏覽器的 `localStorage`，不會跨裝置或瀏覽器同步。清除網站資料、無痕模式，或更換檔案位置／開啟來源，可能影響紀錄。若瀏覽器拒絕儲存，遊戲仍可玩，並會顯示提示。

## 想調整時改哪裡

- 改關卡時間、色數、牆壁位置：`js/levels.js`。`colors` 控制當場顏色種類，`poolSize` 控制可抽選集合大小（取 `GEMS` 前幾種）；未設定 `poolSize` 時預設為九種。
- 改連擊窗口：`js/levels.js` 的 `COMBO_WINDOW_MS`，目前為 5000。成功配對、逾時、暫停／恢復及 PPA 特效共用此常數；洗牌會平移最後配對時間以凍結相同窗口。調整時也要同步首頁與說明文案。
- 版型字元 `X` 表示寶石、`#` 表示牆壁、`.` 表示空白。每列必須等寬，寶石總數必須是偶數；每種顏色至少需要一組。
- `ppaPairs` 指定該關的 PPA 配對數，使用原有 `X` 格位。扣除 PPA 後仍須保留每種普通顏色至少一對；目前第 1／2／3 關分別設為 1／2／3。PPA 洗牌時與其他方塊一起交換位置，數量不變，不會觸發效果。
- 改寶石顏色：`js/levels.js` 的 `GEMS`；改形狀和符號：`js/ui.js` 的 `gem()`。
- 改分數公式：`js/game.js` 的 `choose()` 與 `finish()`，並同步更新遊戲內說明。
- 改整體視覺：`styles.css` 的 `:root` 色票與對應元件。
- 新增或改變牆壁版型後，建議執行規則測試，避免無法靠洗牌解決的尾盤。

## 已完成的驗證

使用 Node.js 內建功能即可選擇性執行，不需安裝任何套件：

```text
node tests/rules.test.js
node tests/timing.test.js
node tests/storage.test.js
node tests/ppa.test.js
node tests/campaign.test.js
```

規則測試涵蓋 700 個隨機棋盤與獨立方向搜尋結果比對、十六關各 35 局（共 560 局）、每個版型的任意最後兩顆位置、洗牌保留位置與數量、強制洗牌保底、逐關集合限制、連擊／星級精確邊界，以及紀錄不被較差成績覆蓋。

流程測試涵蓋暫停 90 秒、第 5／10／15 擊不再額外消除、5 秒精確邊界、倒數歸零失敗、失敗後停止接受配對、過關解鎖、獨立關卡計分、分頁隱藏暫停及離開後的計時清理。

PPA 測試涵蓋非法路徑不觸發、Combo 1／5／7、零對與不足對數、其他 PPA 不被消除且不連鎖、最後一對 PPA 通關、實際得分、一般／減少動畫下的時間凍結，以及演出不同階段的暫停、失焦、隱藏、說明、離開、重玩和洗牌。測試開局資料只存在於測試記憶體，不改玩家存檔。
