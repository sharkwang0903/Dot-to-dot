# 百關活動與正式獎勵服務邊界

目前交付為靜態遊戲、本機完成進度、百篇介紹與獎勵介面。沒有正式會員、訂單驗證、優惠核銷、申領或物流服務；尚未核發優惠或出貨。測試使用 Node VM 的獨立記憶體與測試服務，不設玩家可用的購買勾選、任意訂單號或測試核銷入口。

## 確認的方案

| 階段 | 通關條件 | 購買／贈品 | 次數 |
| --- | --- | --- | --- |
| 主要優惠 | 第 1、2、3 關均已完成 | 買 1 瓶 PPA、送 1 瓶 PPA，另贈 2 個水母公仔；於購買時使用 | 每人一次 |
| 50 關 | 完成 50 個不同關卡 | 一次有效活動購買＋額外 1 瓶 PPA、1 個公仔 | 此階段一次 |
| 100 關 | 完成全部 100 關 | 同一次有效活動購買＋再額外 1 瓶 PPA、1 個公仔 | 此階段一次 |

50／100 關加碼合計 2 瓶、2 個公仔。若使用主要優惠並領完全部加碼，含購買的 1 瓶，合計 PPA 4 瓶、公仔 4 個。可先玩後買，也可先買後玩；百關才驗證購買時，兩個加碼階段都可符合條件。50 關已申領後，百關只增加另一組。

贈送瓶容量、規格、公仔款式、活動期間、領取期限、運費及分次／合併出貨尚待公司確認，程式不自行填入 30 mL 或承諾免費寄送。既有官網商品網址保留於 `js/campaign.js`。

## 本機進度與資料

- `dot-to-dot.v1`：保留自由模式各關星級、分數、耗時、解鎖與音效。
- `ppa-campaign.v1`：保留活動前三關各自的星級、分數、耗時與待閱讀結果。
- `ppa-journey.v1`：只存 `completed` 關卡集合與 `milestonesSeen` 提示紀錄。兩模式相同關卡計一次。舊紀錄須有有效成功星級、非負分數及耗時；不從最高解鎖推算完成數。
- 活動通關可解鎖自由模式下一關，分數不搬移；自由模式前三關也計入入門完成資格。
- 介紹、閱讀與里程碑提示不計時。遊戲中開啟獎勵會暫停，返回後恢復；在結果畫面開啟則返回原結果。
- 本機資料可由玩家更動，也不跨裝置同步。它只供進度展示，不能成為正式購買或實體贈品的領取證明。正式服務需提供可信任的會員通關驗證／同步方案。

## 正式服務介面

日後由正式網站的可信任啟動程式安裝 adapter：

```js
DotGame.Rewards.connect({
  async getStatus() {
    // 經正式會員登入向後端查詢；回傳此會員、此活動的權威狀態。
    return {
      purchase: 'none', // none | pending | verified
      claims: {
        3: 'none',     // none | claimed | shipped
        50: 'none',
        100: 'none'
      }
    };
  },
  async claim({ tier }) {
    // 僅 50、100 階段；後端驗證、原子核銷，回傳相同結構的最新狀態。
    // 主要優惠在正式購買／結帳流程核銷，不由本機按鈕自行標記。
    throw new Error('待串接正式服務');
  }
});
```

這是介面結構說明，未包含可用端點、測試帳號或正式核銷。正式頁面沒有安裝 adapter，因此不出現申領按鈕；只顯示本機門檻、購買待驗證條件與「尚未開放正式兌換」。頁面可先導向既有商品頁，不改網址、不編造兌換連結。

`purchase: verified` 才可讓本機已達成的 50／100 門檻顯示可申領；`claimed` 與 `shipped` 分開呈現，前三關只完成時顯示已解鎖購買優惠。正式狀態不存 localStorage，每次開啟獎勵頁都重新查詢，查詢失敗回到待確認，不沿用舊的已驗證資格。

前端合併同一階段同時重送的請求，申領期間暫停其他階段申領，重新查詢會等待申領結束。這些只改善操作，跨裝置、重新整理、斷線重送的冪等仍須後端保證。

## 待公司與官網提供

1. 正式活動 ID、會員身分、登入與可信任的通關驗證／同步服務；不能直接信任前端傳來的完成集合。
2. 有效購買的商品／訂單條件、訂單驗證介面，以及取消／退款後的資格處理。
3. 主要優惠每人一次的結帳核銷、50／100 各一次的申領介面；以會員＋活動＋階段的唯一條件與交易確保重送不重複發放。
4. 已申領、已兌換、出貨狀態來源；必要的個資與物流流程由正式網站承接，本機不蒐集地址或付款資料。
5. 規格、期間、數量額度、領取期限、運費及出貨安排的正式公告。
6. 全部介紹文案審核，尤其 ID 91～95 的候選題目與最終顯示稿。現階段這五題使用交接已指定的中性備案；來源候選稿及待審狀態保留在資料模組，不顯示給玩家。

## 試玩與驗證

開啟專案 `index.html`，首頁或頁首「活動獎勵」可檢查進度。首次從活動入門完成三關，可選「查看購買優惠」或「繼續第 4 關」；自由通關結果會顯示本關短文與下一關。

`node tests/campaign.test.js` 驗證真實控制器、閱讀與獎勵頁暫停、3→4、49→50、99→100 與一次里程碑；`node tests/journey.test.js` 驗證 100 篇映射、來源／備案分離、舊存檔、資格去重及隔離服務的購買／申領／出貨／重送／退款狀態。完整對照表在 `docs/關卡與內容對照表.md`。

實際瀏覽器及手機觸控尚未驗證：目前自動化瀏覽器先前已拒絕本機 `file://` 網址，本次環境檢查亦無可用的已開啟遊戲頁；未改用其他傳輸或瀏覽器協定繞過限制。UI 已加入窄螢幕排版、可捲動 dialog 與最少 48px 的主要操作按鈕，但程式測試不等於實際手機檢查。
